# 2026 大模型选型：按任务给每个请求选对模型，切换不改代码

*作者：NewtonRouter 团队 · 发布于 2026-11-11 · 价格核实于 2026-11-10*

2026 年选大模型最快的方法，是别再只选一个大模型。把你手上的每类任务——批量分类、日常产品功能、高难推理——分到入门、中档或旗舰三档。在供应商自己的定价页上核实每一档的成本，并把切换成本压到足够低，让一次重新评估只改两个字符串，而不是一次重写。

这一点之所以重要，是因为能在「大模型选型」上排到前面的内容，多半来自两类来源：以自家注册优惠收尾的网关厂商软文，以及仍在推荐早已从供应商页面轮换下线的旧阵容的第三方指南。两者都有用，也都不中立。本指南是系统方法的那一版：一张用官方、可溯源价格标定的任务到档位地图，一份诚实的「切换时会坏什么」清单，一个一个下午就能落地的最小路由模式，以及一套跑在你真实提示上的测试方案。坦白说明：我们自己也在运营网关，所以请把本文当作又一个可供交叉核对的声音，去和你的自测结果对照，而不是最终结论。

本文所有可核验的内容都保持可溯源。价格来自四家供应商定价页，截至 2026-11-10；竞品行为逐条归属其来源；凡厂商没有给出基准的宣称，一律标注为厂商口径。

> **关键要点**
> - **档位是 40×-100× 的价差，不是口味。** GPT-6 Luna 官方标价每百万 token `$0.10/$0.50`，GPT-6 Astra 是 `$10/$50`——100 倍（[openai.com/api/](https://openai.com/api/)，2026-11-10 核实）。Claude Haiku 5.5 到 Opus 5.5 是 40 倍（[claude.com/pricing](https://claude.com/pricing)，2026-11-10 核实）。
> - **切换模型是两个字符串的改动。** 在 OpenAI 兼容端点上，你只改 base URL 和模型标识符；SDK 与业务代码不动。
> - **会坏的是语义，不是语法。** max_tokens 行为、工具调用 schema、结构化输出保证、上下文阈值、系统提示处理——五项，清单见第 4 节。
> - **显式档位让模型身份始终可知。** 自动路由模式按请求挑模型；要么配每请求模型日志，要么选承诺不静默降级的网关。
> - **本文每个价格都可溯源。** 全文带核实日期、来源 URL 与厂商口径标注；不引 benchmark 数字，不引无基准的省钱百分比。

## 把一个模型写死的代价

2026 年 2 月，一家四人物流创业公司把所有客服邮件都跑在工程师做代码评审用的同一个旗舰模型上。配送时段咨询、地址更正、订单状态查询——大多是短小、模板化的回答——却按旗舰输出价计费。月账单落在 2,100 美元出头，创始人追溯后发现，约四分之三来自根本不需要那个档位的工单流量。什么都没坏。他们只是从未问过：六个月前定下的那个模型，哪些任务配得上它。

错不在旗舰模型本身，而在于用同一个模型应对一切，因为档位选择看起来像口味问题。它不是。它是量级问题，而且官方价格让这一点可以直接度量。

在 OpenAI 自己的页面上，GPT-6 Luna 标价为每百万 token 输入 `$0.10`、输出 `$0.50`，而 GPT-6 Astra 标价为 `$10/$50`——入门档与旗舰档之间是 100 倍差距（[openai.com/api/](https://openai.com/api/)，2026-11-10 核实）。在 Anthropic 的页面上，Haiku 5.5 对 Opus 5.5 是同方向的 40 倍差距（[claude.com/pricing](https://claude.com/pricing)，2026-11-10 核实）。当选项空间的两端相差两个数量级时，「我们该用哪个模型」其实是两个问题：这个任务该用哪一档，以及这一档里该用哪个模型。按这个顺序回答。

**第二**，旗舰档通常是 agentic 编程工作的落点——长工具调用链、大仓库上下文、成倍放大的重试成本——所以问「编程该用哪个模型」的读者，应从旗舰行出发，只有当负载确实更轻时才往下移。grok-4.6 进场价 `$2/$6`，Opus 5.5 `$4/$20`，Astra `$10/$50`：旗舰工作的三个价位；这里不给 benchmark 数字，因为厂商 benchmark 是最先过时的东西。

## 切换模型时真正改变的是什么

比你担心的少，比教程说的多。在 OpenAI 兼容的网关上，切换模型意味着只改两个字符串：base URL 和模型标识符。你的 SDK、鉴权方式、重试逻辑和业务代码原样不动。机械层面，迁移的全部就是这些。

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://newtonrouter.com/v1",
    api_key="YOUR_KEY",
)

resp = client.chat.completions.create(
    model="gpt-6-luna",   # was: gpt-6-astra
    messages=messages,
)
```

把 `gpt-6-luna` 换成 `claude-opus-5-5` 或 `gemini-4-argon`，同一个客户端、同一份消息数组、同一套工具定义，就到达了另一个家族。[NewtonRouter 模型列表页](https://newtonrouter.com/models)列出了通过这个单一端点可调用的 GPT、Claude、Grok、Gemini 四家模型族，第二个字符串是查表，不是调研项目。

注意这个说法不是什么。它不是「零配置」。两个字符串是机械成本；语义成本藏在新家族如何解读你发送的内容里，也就是下一节。给字符串留一个下午、给清单留一天并且一次做完的团队，能顺利收工；只给十分钟预算的团队，上线的是回归。

## 会坏什么：诚实的兼容性清单

每一篇机制教程都说「改个模型字符串就行」。没有一篇告诉你改了之后什么会变。这是诚实的版本——五个模型家族之间真实存在差异的地方，按咬人的频率排序。

换模型家族时，会坏的是五件事：max_tokens 与输出长度行为、工具调用 schema 的严格度、结构化输出保证、上下文窗口阈值及其价格阶梯，以及系统提示处理。它们都不会在第一次调用时报错——而是以截断输出、解析失败或悄悄变差的答案的形式浮出水面。

1. **max_tokens 与输出长度行为。** 各家族在截断什么、停止序列如何与之交互、推理型模型在产出可见文本前消耗多少预算上都不同。在一个模型上觉得宽裕的上限，换一个模型就开始削尾巴。*测试方法：固定上限，同一提示，对比输出在哪里停。*

2. **工具调用 schema。** 函数名的严格度、并行工具调用支持、参数类型上的怪癖因家族而异。在一个模型上顺利通过的工具链，换一个模型可能改错参数名或漏掉调用。*测试方法：你最复杂的三条工具链，断言调用参数本身，而不只断言最终答案。*

3. **结构化输出保证。** JSON 模式在各处的契约不一样。有些模型在 API 层强制 schema；有些需要你在提示里反复强调、偶尔仍会漂移。*测试方法：每个候选模型上把你的抽取 schema 跑五十次，统计解析失败数，而不是只看成功数。*

4. **上下文窗口及其价格阶梯。** 阈值是真实存在的，而且是计价的。Claude Haiku 5.5 在提示跨过 10 万 token 后从 `$0.10/$0.50` 变为 `$0.50/$2.50`；grok-4.6 自 20 万 token 起整条请求按长上下文费率计价（[claude.com/pricing](https://claude.com/pricing)、[docs.x.ai](https://docs.x.ai/developers/pricing)，2026-11-10 核实）。换家族可能同时改变装得下什么、以及同一个请求花多少钱。

5. **系统提示处理与指令风格。** 详简偏好、排版习惯、对指令的字面程度都不同。在一个家族上调好的提示，过拟合了它的怪癖，换到另一个家族会无声地失效。*测试方法：你最常用的十条系统提示，盲读并排输出。*

这些都不是永远留在同一个模型上的理由。它们是上线前要测试、上线后要保留每请求模型日志的理由——这样当某处漂移时，你能叫出漂移的那个模型的名字。

## 一个最小路由模式：默认低价，按信号升级

能在生产环境里活下来的路由模式都很小。一切机器可校验的任务默认走入门档；面向用户的生成走中档；旗舰档留给被证明需要的任务；按信号升级，而不是按期望升级。

```python
TIER_BY_TASK = {
    "classify_ticket":  "gpt-6-luna",     # 入门：高吞吐、可校验输出
    "draft_reply":      "gpt-6.1-sol",    # 中档：面向用户、中等风险
    "postmortem_analysis": "gpt-6-astra", # 旗舰：高难推理、低频
}

def run(task, messages):
    model = TIER_BY_TASK[task]
    resp = client.chat.completions.create(model=model, messages=messages)
    log(task=task, model=model, tokens=resp.usage)   # 每个请求都记模型身份
    return resp
```

升级是团队最容易省掉、然后后悔的部分。当入门模型的置信信号下降、校验失败或用户标记了某个回答，就把该条目升到上一档重试并记录这次升级。你只为困难的长尾付旗舰价，而不是为整个分布。一个加成细节：如果入门档提示共享稳定前缀，OpenAI 把缓存输入标为大致标准输入的 10%（[platform.openai.com/docs/pricing](https://platform.openai.com/docs/pricing)，2026-11-10 核实），批量链路越标准化就越便宜。

这个多模型路由模式需要一个落点，而落点是与地图分开的另一个决策：自托管代理、直连集成或托管网关，各自在可靠性、留存与广度上做了不同的取舍。[哪款 LLM API 网关适合你的技术栈](openrouter-alternatives-2026.md)，我们在网关指南里单独回答。

## 自动路由 vs 显式档位

自己维护地图之外的主要替代，是让路由器来挑。OpenRouter 在其官网列出 `openrouter/auto`：按请求用实时数据挑选模型与供应商，故障转移默认开启（[openrouter.ai](https://openrouter.ai/)，2026-11-11 核实）。MegaRouter 也推广自己的 Auto 模式，并附带我们在此不复述的厂商自称省钱数字——因为它们没有给出基准（[megarouter.com](https://megarouter.com/zh/blog/megarouter-openai-api-compatibility-ai-model-migration-costs)，2026-11-11 核实）。

自动模式并不是错的；它们优化的是另一个目标。它们替你省掉了本指南要求你做的映射工作，对探索型负载这是笔公平的交易。代价是身份。当路由器来挑，你得到的模型就是它那一瞬间选中的模型，而只有当下游有什么东西把它记下来，你才知道是哪一个。显式地图的每一个好处——每任务可预测的成本、每任务稳定的质量、质量漂移时的书面痕迹——都取决于知道这个答案。丢了模型身份，三样一起丢。

> **迷你故事：安静的两周。** Ines 经营一家两人小机构，为暖通公司做通话记录摘要。8 月她打开了路由器的 auto 模式，从此不再想模型的事。营收在涨，投诉没来——直到 9 月中旬，一位客户转来了把预约时间搞混的记录。她翻查请求日志才发现：大约两周里，路由器在高峰时段的下午一直在用更小的模型应答。没有任何报错。只是答案悄悄变差了。她把路由重建为三个显式档位，并要求每个响应对象都带模型名，之后才重新信任这条流水线。

在这里，网关的降级政策不再是一条合规细节。一个承诺不静默降级的网关——你要的模型就是应答的模型，否则响亮地失败——让显式档位可信，也让自动模式可审计。各厂商存储与转发什么也要读清楚：AnyModel 宣传一种它称为 Ghost Mode 的零留存 key 模式，并附厂商自述的限定——上游供应商仍会收到你的提示词（[anymodel.org](https://anymodel.org/en/blog/how-to-pick-the-right-model-for-each-task-and-save-money)，2026-11-11 核实）。零留存是这个市场上真实的差异点，而且不止一家网关如此宣称，所以请比较各家的实际策略，而不是形容词。

## 先在你自己的提示上测试，再做承诺

无论地图的来源多么可靠，都替代不了你自己的流量。能在一周内产出决策的测试流程：

1. **从生产日志收集二十到三十条真实提示**，按你的真实流量构成加权，而不是按最有趣的边界情况。
2. **每个档位选两个候选盲测。** 输出里的模型名先抹掉再给人读；品牌熟悉度会污染判断。
3. **按你的标准打分，而不是通用标准。** 分类看你自己的标签、抽取看你自己的 schema、语气看你自己的品牌声音。
4. **测试期间记录每个响应背后的模型**，让每个分数都能归因到具体模型与具体日期。
5. **每季度重跑。** 模型阵容会轮换、价格会跳档，11 月正确的档位分配到 2 月可能就错了。

> **迷你故事：过期的那串字符。** 一支九人开发者工具团队把一个模型标识符硬编码在四个服务里。供应商以更名后的继任型号退役了这个别名，某个寻常的周二部署开始失败——因为那串字符活在每个服务里，修复动到了所有服务。他们事后做的迁移，把标识符挪进一个按环境读取的单一配置项——一旦它成为单一取值，在批量链路上试用继任型号的中档兄弟，就从「一个项目」变成「改一行」。教训不是「避免更名」，那不由你控制；而是把犯错的成本压低，因为更名总会来。

[NewtonRouter 文档](https://newtonrouter.com/docs)覆盖了本节用到的 OpenAI 兼容端点与请求字段，如果你想在统一端点上而不是四家供应商控制台里跑这套流程。

## 常见问题

**切换模型需要改代码或 SDK 吗？**
SDK 不用改。在 OpenAI 兼容端点上，切换模型意味着只改两个字符串：base URL 和模型标识符。你的 SDK、鉴权方式与业务代码原样保留。真正需要留意的是语义兼容：max_tokens 行为、工具调用 schema、结构化输出保证、上下文阈值与系统提示处理在各个模型家族之间都不同，所以在路由生产流量之前，先过一遍兼容性清单。

**分类和抽取任务该用哪个档位？**
多数情况下用入门档。分类和抽取是高吞吐、短输出、答案可校验的任务，正是入门档模型的定价场景：GPT-6 Luna 每百万 token `$0.10/$0.50`，Claude Haiku 5.5 `$0.10/$0.50`（提示不超过 10 万 token），Gemini 3.5 Flash-Lite `$0.30/$2.50`（[openai.com/api/](https://openai.com/api/)、[claude.com/pricing](https://claude.com/pricing)、[ai.google.dev](https://ai.google.dev/gemini-api/docs/pricing)，2026-11-10 核实）。先在你自己的 schema 上核实准确率，然后只把入门档标记或未能处理的条目升级到中档或旗舰档。

**该让网关自动挑模型吗？**
只有在你查得到它挑了什么的前提下。OpenRouter 的 `openrouter/auto` 按请求挑选模型与供应商，故障转移默认开启（[openrouter.ai](https://openrouter.ai/)，2026-11-11 核实）；MegaRouter 也推广类似的 Auto 模式。自动模式省掉了映射工作，但也省掉了「你请求的模型就是应答的模型」这层保证。如果你用自动模式，请要求每请求模型日志并每周抽查。如果每个响应背后的模型不可见，请选显式档位。

**把任务路由到更便宜的模型到底能省多少？**
在我们的算例里，上限就是把哪部分负载移走，就能吃到入门到旗舰的全部价差。以每月 1000 万输入 token、200 万输出 token 计：GPT-6 Luna（每百万 `$0.10/$0.50`，[openai.com/api/](https://openai.com/api/)，2026-11-10 核实）花费 `$2.00`。同样的组合在 GPT-6 Astra（`$10/$50`）上花费 `$200.00`——100 倍差距。同一组合在 Claude Haiku 5.5 上是 `$2.00`，在 Opus 5.5 上是 `$80.00`——40 倍差距。你的百分比取决于入门档能诚实承接多大比例的流量，请用你自己的日志计算，不要轻信厂商的标题数字。

**从一个模型家族换到另一个，会坏什么？**
五件事，按咬人的频率排序：max_tokens 与输出长度行为、工具调用 schema 的严格度、结构化输出保证、上下文窗口阈值及其价格阶梯、系统提示处理与指令风格。它们都不会在第一次调用时报错。它们以截断输出、解析失败或悄悄变差的答案的形式浮出水面——这正是兼容性清单存在的理由，也是切换前要在真实提示上测试的理由。

**我该多久重新评估一次模型选择？**
每季度一次，外加触发条件。每季度重跑一次盲测，能接住模型发布的稳定漂移。不该等到季度的触发条件包括：模型更名或弃用公告、促销价到期（Gemini 4 Argon 的 `$2/$10` 促销价运行至 2026-11-30，2026-12-01 起 `$4/$20`，[ai.google.dev](https://ai.google.dev/gemini-api/docs/pricing)，2026-11-10 核实）、日志里的质量回归，或大到跨档位的负载变化。把切换成本保持在两个字符串，重新评估就一直便宜。

## 结语：按任务路由，按请求核验

三个动作承载了大部分价值。先在争论模型之前把任务映射到档位，因为 40×-100× 的官方价差让档位决策大于模型决策。把切换当作附带语义清单的两个字符串改动，既不当成重写，也不当成无事发生。并且让每次请求上的模型身份可观察——无论你的路由是显式还是自动，上文「安静的两周」就是路由不可观察的代价。

这里真正的元技能，是把重新评估变便宜。模型阵容会轮换、促销价会到期、今天属于旗舰档的负载下季度可能就不属于。如果切换只要两个字符串加一轮测试，你会真的去重新评估；如果它要一次迁移，你会为自己再撑一年找理由，留在早已不合身的档位上。
