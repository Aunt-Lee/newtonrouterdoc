# 2026 LLM API 价格对比：官方标价 vs 你实际付出的金额

*由 NewtonRouter Team 发布 · 2026 年 11 月 10 日 · 最后核实 2026 年 11 月 10 日*

**一份只看公布费率的 LLM API 价格对比，只讲出了故事的三分之一。** 官方标价不是网关的挂牌价，而账单上的数字又是第三个数值——它们是三个彼此独立的数字。一个宣称每百万 token 的价格，会被拆成输入与输出两段，再叠上网关费用、缓存与上下文档位，才变成你真正支付的金额。

Elena 是一家 12 人 SaaS 公司的后端工程师，她为客服机器人按月预算 400 美元，结果收到一张 1180 美元的发票。没有任何东西出错。她只比较了一个模型的输入价，却漏掉了三件事：输出 token 的价格是输入的几倍、她那条冗长的系统提示从未被缓存，而购买额度本身就带着一张费率卡从不显示的费用。

如果你曾把两张定价页并排摆在一起然后放弃，那不是你的问题：它们衡量的是不同的东西。本指南给你一张在任何供应商上都通用的核算表，再把它套用到四大模型家族及其之间的费用结构上去。你会看到一份带来源的 2026 价格表、token 计费背后的机制、逐厂商的标价拆解、标价与到手价的缺口、隐藏成本、一个三段式算例、一份七点清单，以及六个价格相关的常见问题。价格只是决策的一个维度；当你知道自己要付多少钱之后，还得去挑供应商与部署方式，所以那一侧的问题可以去看[对比 OpenRouter 替代品](openrouter-alternatives-2026.md)。

## LLM API 是如何计价的：输入、输出、缓存与推理 token

大多数定价页为每个模型只显示一个数字。而你的账单由好几个数字构成，广告数字和真实数字之间的那道缺口，正是预算崩坏的地方。

### 2.1 输入与输出

**输入 token** 是你发出的提示。**输出 token** 是模型生成的内容。供应商把输出定得比输入高，因为生成是顺序工作，而读取输入可以并行批处理。在 GPT-6 Astra 上，输出 `$50` 对输入 `$10`，是 5 倍的关系。一个输入很长、输出很短的摘要服务，和一个提示很短、补全很长的代码智能体，即便用同一个模型，有效单价也截然不同。第三方调研把输出对输入的比例标在多数模型的 2–5× 区间（[tokenmath.net](https://tokenmath.net/llm-cost-calculator)、[tokenando.ai](https://tokenando.ai/learn/how-ai-api-pricing-works)，2026 年 10 月）；把它们当作结构性的参考，而不是官方价格。

### 2.2 提示词缓存

**缓存输入 token** 是供应商可以复用的、重复出现的提示片段，定价远低于普通输入。OpenAI 把缓存输入标为大致标准输入的 10%（[platform.openai.com/docs/pricing](https://platform.openai.com/docs/pricing)，2026-11-10 核实）；Anthropic 在 5 分钟 TTL 下报缓存，并有独立的读、写费率。它只有在稳定的前缀被复用且确实命中时才划算。

> **迷你故事：那个没人开启的缓存。** 2026 年 6 月，一家两人文档创业公司 Tidepool 用一条 3000 token 的系统提示跑客服助手，每条调用都重复它。创始人 Sam 看着账单上涨，以为模型就是贵。一周的请求级日志却显示相反：70% 的输入 token 是逐字相同的样板，每次都按完整输入费率计费。在那段共享前缀上开启提示词缓存，输入那一行应声大降，而模型一个没换。费率卡从未算错；是这个团队一直在为重新发送并不需要的 token 付钱。

### 2.3 批量处理

**批量处理** 用延迟换取输入输出上的一项公开折扣。OpenAI、Anthropic 和 Google 都把批量列为标准的 50%（[platform.openai.com/docs/pricing](https://platform.openai.com/docs/pricing)、[claude.com/pricing](https://claude.com/pricing)、[ai.google.dev](https://ai.google.dev/gemini-api/docs/pricing)，2026-11-10 核实）。它适合夜间分类或评测这类异步工作，不适合实时聊天。在把它写进模型之前，请在各供应商自己的文档上确认具体数字。

### 2.4 按输出计费的推理 token

会"先思考再回答"的模型会发出**推理 token**，通常按输出费率计费，尽管用户从不看见它们。一个短短的可见答案，背后可能藏着一条巨大的隐藏输出。如果你开启了推理档位，请单独记录它的 token 数；这是账单在没有改一行代码的情况下悄悄翻倍的最简单途径（[tokenmath.net](https://tokenmath.net/llm-cost-calculator)）。

### 2.5 长上下文档位、区域与汇率

模型名字不等于价格。供应商按**上下文长度**、**处理模式**和**区域**来变价。OpenAI 在 2026-03-05 及之后发布的模型上，对数据驻留端点加 10% 的上浮；Anthropic 对美国境内推理取 1.1×、快速模式取 2×；xAI 在提示达到 20 万 token 后把整条请求大致翻倍；Google 在 20 万阈值上拆分多个模型。货币转换与本地税费，给在美元之外结算的团队又加了一层。比较两家网关时，请把这些变量保持恒定，否则你是在拿一个批量任务和一个优先请求比价。

### 2.6 成本公式

一旦把各个桶分开，算术其实很简单：

```
账单 = (输入 token ÷ 1,000,000 × 输入单价)
     + (缓存输入 token ÷ 1,000,000 × 缓存单价)
     + (输出 token ÷ 1,000,000 × 输出单价)
     + 工具调用费用
     + 平台费
实际单价 = 账单 ÷ (总 token ÷ 1,000,000)
```

有两处细节比公式本身更重要。**用你自己的 token 组合**，因为一条基准提示对你生产环境的智能体循环毫无说明意义。**把平台费应用到整张账单上**，而不只是输入那一行，因为充值上的百分比会随着你花的每一笔钱一起放大。这正是每个算价网站背后的算术（[moneydeck.io](https://moneydeck.io/tools/ai-api-cost-calculator)、[tokenmath.net](https://tokenmath.net/llm-cost-calculator)），也是下面这张核算表要用的方法。

## 官方标价 vs 网关到手价：缺口从何而来

这是一份有用的 **LLM API 价格对比**的核心：公布的费率和你发票上的数字之间的差别。竞品几乎总是只展示一层。一份中立的对比，要把三层都展示出来。

### 4.1 网关收费的三种方式

| 网关如何收费 | 费用落在何处 | 示例（来源） |
|---|---|---|
| 透传 + 充值手续费 | 在你购买额度时收取，从不按单次请求 | OpenRouter：不做每 token 加价；Standard 5.5%、Business 8%、加密 5%（[openrouter.ai/pricing](https://openrouter.ai/pricing)） |
| 模型成本上的固定加价 | 随你发出的每个 token 放大 | Requesty：模型成本上加 5%，BYOK 为 0%（[requesty.ai](https://www.requesty.ai/)） |
| 月度平台 + 每次请求 / 每日志费用 | 随请求与日志量放大，而非 token | Portkey：Pro 每 10 万次请求 $49/月，额外每 10 万次 $9（[portkey.ai](https://portkey.ai/docs/product/product-feature-comparison)） |
| 自托管代理 | 没有平台费；基础设施归你 | LiteLLM：开源 `$0 永久`，企业版永不按 token 计费（[litellm.ai](https://www.litellm.ai/pricing)） |
| 预付转售容量 | 一条厂商自报、低于官方标价的折扣 | KissAPI 与 Crouter 都宣传折扣；这些数字是厂商自报、未经独立核实 |

*截至 2026-11-10，来源：右列链接的官方定价 / 文档页；竞品的折扣声明是厂商自报、未经独立核实，需要附上模型、档位与日期才能确认。费率会变，提交预算前请以供应商官方定价页为准。*

其中好几项是对手的权益而非收费：LiteLLM 的开源构建可免费自托管，Portkey 提供每月 1 万次请求的免费开发档，OpenRouter 列出每月免费额度与 25+ 个免费模型，NanoGPT 在其网页档上有一个免费模型，Crouter 声明没有免费档。这些是竞品事实，不暗示在其他地方有任何对等的权益。把它们留在各自的列里；一个免费档（第四类）不是一种 token 价格（第一类）。

### 4.2 同一个模型，跨主机相差 13× 到 31×

这道差距不是理论。一家追踪 235 家供应商、9000 条报价的第三方聚合器发现，同一个开源模型在 126 家主机上相差 13.2×、122 家上 25.1×、113 家上 31.3×、96 家上 30.4×，数据同步于 2026-11-09（[llmpricing.dev](https://llmpricing.dev/)）。这是第三方追踪器的一条景观观察，不是官方价格来源。它告诉你为什么"模型 X 的价格"在没有点名主机之前，根本不是一个成形的问题。该追踪器还发布一种用 `输入 × 0.75 + 输出 × 0.25` 加权的混合价——那是一种**第三方估算方法**，不是官方标价，而且永远不能混进一张标着"官方"的表里。

### 4.3 一个文档化的示例：挂牌价 vs 到手价

以 GPT-6 Astra 每百万 token `$10/$50` 为例。在透传网关上，token 那一行与 OpenAI 的页面分毫不差，没有每 token 加价。费用出现在别处。[OpenRouter 的定价页](https://openrouter.ai/pricing) 写明，推理按各供应商的标价在各计划上计费，手续费在你购买额度时收取：Standard 5.5%、Business 8%，从不按单次请求。所以 Standard 上一张 $100 的 token 账单，要消耗约 $105.50 的额度。BYOK 流量每月有 `$25,000` 标价等值的免平台费额度，超出部分收 5%（[openrouter.ai/docs/faq](https://openrouter.ai/docs/faq)，2026-11-10 核实）。挂牌价和到手价都是真实的；它们只是不同的数字。

### 4.4 为什么更低的挂牌价并不自动等于更低的账单

费率卡为一个档位上一次成功的调用定价。到手价还要加上充值与 BYOK 费用、订阅与日志超额、推理与长上下文 token、工具、重试，以及税费。它还加上一项信任成本：如果一个请求被悄悄用一个更便宜的替身来服务，质量就会下滑，而你的团队要花上几个小时去调试一段从未出错的代码。一个经由静默模型降级而来的更低挂牌价，不是更低的账单；它是另一种产品。文档说明了如何核验每次请求确切调用的模型与渠道，而一份网关清单能帮你查清哪些供应商会记录这个身份。

## 价目表不会告诉你的隐藏成本

费率卡告诉你一次成功调用花多少钱。你的发票告诉你一个月真实流量花多少钱。二者之间的差额，大部分由这些项目构成。

### 5.1 充值与 BYOK 费用

充值上的百分比适用于整个余额，而非单次请求，所以它随着你花的每一笔钱一起放大。OpenRouter 在 Standard 充值上收 5.5%、最低 `$0.80`，加密收 5%，Business 收 8%；自带 Key 流量每月 `$25,000` 标价等值推理之前免平台费，之后收 5%（[openrouter.ai/pricing](https://openrouter.ai/pricing)、[openrouter.ai/docs/faq](https://openrouter.ai/docs/faq)）。Requesty 在模型成本上加 5% 的加价，但 BYOK 为 0%（[requesty.ai](https://www.requesty.ai/)）。NanoGPT 标榜"无加价"的标价，但有两项可选例外：手动指定供应商或使用 BYOK 各加 5%（[nano-gpt.com](https://nano-gpt.com/pricing)）。"无加价" 很少是无条件的；请读例外条款。

### 5.2 订阅、日志超额与席位档

有些网关几乎不碰 token。Portkey 的 Pro 计划是每 10 万次请求 `$49/月`、额外每 10 万次 `$9`，其免费开发档允许每月 1 万次请求、三天日志保留（[portkey.ai](https://portkey.ai/docs/product/product-feature-comparison)）。NanoGPT 的 PRO 订阅是 `$12/月`（[nano-gpt.com](https://nano-gpt.com/pricing)）。LiteLLM 的企业版按年报价，永不按 token 计费（[litellm.ai](https://www.litellm.ai/pricing)）。在这里，成本曲线追随请求与日志量，至少与追随 token 一样多，所以一张只看 token 的表格会低估它。

### 5.3 自托管基础设施

自托管去掉了平台费，却换来一个数据库、一份缓存、发布打补丁、值班轮转与容量规划。对一支有平台工程师的团队，这笔交换常常是对的；对没有的团队，那套免费软件是清单上最贵的一项。把基础设施与工程时间当作任何总拥有成本模型里真实的一行，即便任何费率卡都不会显示它（[therouter.ai](https://therouter.ai/blog/ai-model-router-pricing-cost-comparison-2026)）。

### 5.4 失败请求、重试、税费与承诺消费

计费政策各不相同。[OpenRouter 写明](https://openrouter.ai/pricing)，一次出错的尝试不会为模型 token 收费，所以有了故障转移，你只为真正作答的那次运行付费。但流式取消并非每个上游供应商都支持，所以在那些路由上，一个被中断的响应仍可能产生费用。早早短路的智能体循环，是这类浪费的常见来源。在比较两张发票之前，请加上工具调用（网络搜索、文件搜索、容器、图像）、区域上浮、货币转换、本地税费，以及任何起充门槛或承诺消费条款（[ai-rockstars.com](https://ai-rockstars.com?p=12712/)）。

> **迷你故事：那次自己回本的故障转移。** 一支金融科技后端团队曾把生产流量只路由到单一供应商，并因一次区域中断而损失了一个周六。在迁到带自动故障转移与按 Key 预算的网关之后，他们的 AI 事故页在两个季度里降到零。那条支出上限还逮住了一个配置错误的智能体循环——它本会在夜里把一个失败调用重试几千次。他们当初选这个网关是为了可靠性，但被它护住的那个账目条目，其实是账单。

### 5.5 静默降级的税

如果一个网关悄悄用一个更便宜的替身来服务一条旗舰请求，挂牌价就失去了意义：你为一个模型付费，收到的却是另一个。没有错误，也没有标记，所以延迟与成本的仪表盘看起来正常，而质量在漂移。请坚持要求每次请求都带有记录确切模型与渠道的元数据，并把文档化的零留存与"不静默降级"政策当作架构，而不是首页上的一句形容词。文档涵盖了该记录什么；要更完整地了解哪些供应商暴露了这个身份，见[哪些网关真正值得纳入](openrouter-alternatives-2026.md)。

当你确定哪些费用层级适用于你的用量后，迁移生产流量前，可先 **[查看套餐 →](https://newtonrouter.com/plans)**。

## 算例：同一个工作负载，三条访问路径

公式只有在你能跑起来的时候才有用。这里把一个工作负载用三种方式计价。**所有假设都已声明；每个单价都有来源与日期；结果是示意性的，不是报价。**

**假设。** 每天 1 万次请求、持续 30 天 = 每月 30 万次请求。每次请求：2000 输入 token + 500 输出 token，无缓存，标准处理，短上下文。月度总量：6 亿输入 token，1.5 亿输出 token。模型：GPT-6.1 Sol，官方标价每百万 `$2 输入 / $10 输出`（[openai.com/api/](https://openai.com/api/)，2026-11-10 核实）。

| 费用项 | A：直连供应商 | B：通道网关（Standard） | C：折扣转售商（厂商自报） |
|---|---:|---:|---:|
| 输入（6 亿 token） | $1,200.00 | $1,200.00 | $300.00（假设值） |
| 输出（1.5 亿 token） | $1,500.00 | $1,500.00 | $375.00（假设值） |
| 充值手续费 | — | $148.50（5.5%） | — |
| **月度合计** | **$2,700.00** | **≈ $2,848.50** | **≈ $675.00（未核实）** |

*截至 2026-11-10，来源：[openai.com/api/](https://openai.com/api/)（GPT-6.1 Sol 标价）与 [openrouter.ai/pricing](https://openrouter.ai/pricing)（Standard 5.5% 充值手续费）。这两个官方来源只覆盖 A、B 两列的单位价与 Standard 手续费，不覆盖 C 列。基于所述假设的示意性算术；单位美元。**Path C 假设某转售商对同一模型标 $0.50 输入 / $2.50 输出每百万——一个假设数字，并非任何厂商公布的费率：属于厂商自报、未经独立核实，此处仅作为待验证的假设，而非真实价格。** 费率会变，提交预算前请以供应商官方定价页为准。*

Path A 是官方标价的算术。Path B 加上了 Standard 充值上一项已记录的 5.5% 费用；在 Business 上会是 8%，而 BYOK 在每月 `$25,000` 标价等值推理之内不收平台费。Path C 看起来最小，也是唯一你无法从一张公开费率卡上审计的一项：一条折扣，只有附上模型、档位与日期，并且响应确实由你要求的那个模型来服务时，才有意义。

> **迷你故事：那场并不存在的折扣。** Marcus 经营一家独立的开发者工具公司，把流量迁到了一家宣传"大幅低于官方标价"的转售商。六个星期里，他的客服回复感觉更弱了，但延迟与成本的仪表盘看起来正常。他终于去记录原始响应，发现约三分之一被标记为高级的调用，是由一个更便宜的模型服务的，没有错误，也没有标记。纸面上他在省一个百分比；实际上他买的是另一种产品，并搭上自己的时间去调查那次质量下滑。"我不需要一个更低的标题价，"他说，"我需要的是我要求的那个模型。" 他迁到了一个逐请求记录确切模型与供应商的网关。

教训不是折扣不好。教训是：一个没有附上模型名、档位和日期的费率，不是你能核实的费率。先把核算表建好，再用你排名前十条的真实提示，跑过两三个入围选项，比较生成的发票。

## 如何公平比较 LLM API 价格：7 点清单

在提交预算之前，对每一个候选都跑一遍这七项检查。

1. **统一成每百万 token 的美元价。** 把每个报价都换算成相同的单位和货币。
2. **把输入与输出分开列。** 永远不要把它们压成一个混合数字；把缓存输入当作第三行来读。
3. **为每一行标注官方页面与核实日期。** 官方标价只来自供应商自己的定价页；把第三方估算和混合价方法都标注为这类。
4. **对齐档位与上下文阈值。** 记下标准 vs 批量、短 vs 长上下文，以及任何区域上浮。
5. **加上费率卡之外的每一项费用。** 充值与 BYOK 费用、订阅、日志超额、工具、重试、税费与汇率。
6. **逐请求核实模型身份。** 确认实际服务的确切模型与渠道，而不只是一个绿色的状态点。
7. **上线前用你真实的提示再测一遍。** 在模型、提示或路由有任何变动后，重复这张核算表。

这些检查能防止最贵的那种后果：围绕一个从未真实存在过的数字重建预算，然后六个月后再迁移一次。

## 常见问题

**2026 年每 100 万 token 的 LLM API 价格是多少？**
没有一个统一的价格。截至 2026-11-10，官方标价每百万 token 从 GPT-6 Luna 的 $0.10/$0.50 一直到 GPT-6 Astra 的 $10.00/$50.00（[openai.com/api/](https://openai.com/api/)）。一家第三方追踪器把数百个模型的混合区间标为每百万 $0.02–$285.00（[tokenando.ai](https://tokenando.ai/learn/how-ai-api-pricing-works)，2026 年 10 月），那是一条景观估算，不是官方价格。输出 token 的价格通常是输入的几倍，所以两列都要看。费率会变，提交预算前请以供应商官方定价页为准。

**官方标价和网关实际收取的费率有何区别？**
这是三个数字。**官方标价**是供应商公布的每百万 token 费率。**网关挂牌价**是网关费率卡上显示的数字，要么是标价的透传，要么是一条厂商自报的折扣。**实际到手价**再加上你这套 token 组合上的每一项费用。OpenRouter 透传供应商标价、不做每 token 加价，但 Standard 收 5.5%、Business 收 8% 的充值手续费（[openrouter.ai/pricing](https://openrouter.ai/pricing)，2026-11-10 核实）。

**LLM API 的费用是如何计算的？**
费用 =（输入 ÷ 100 万 × 输入单价）+（输出 ÷ 100 万 × 输出单价）。再加上缓存输入 token 按它自己的更低单价计费，应用批量或长上下文调整，并叠上平台费、工具调用费与重试。最后用总额除以总 token 量，得到你的每百万有效单价（[tokenmath.net](https://tokenmath.net/llm-cost-calculator)、[moneydeck.io](https://moneydeck.io/tools/ai-api-cost-calculator)）。首页上那个百分比替代不了这笔算术。

**为什么我的 LLM API 账单比价目表显示的高？**
费率卡为一个档位上一次成功的调用定价。你的发票还要加上高于输入的输出现格、按输出计费的推理 token、长上下文与区域上浮、充值与 BYOK 费用、订阅与日志超额、工具调用、部分供应商仍会收费的失败或中断请求、税费，以及货币转换。记录每次请求背后确切调用的模型与渠道，你才能把这些账目分开（[therouter.ai](https://therouter.ai/blog/ai-model-router-pricing-cost-comparison-2026)、[ai-rockstars.com](https://ai-rockstars.com?p=12712/)）。

**提示词缓存和批量处理真的能降低 LLM API 成本吗？**
能，但有前提。OpenAI 把缓存输入标为大致标准输入的 10%，批量处理为标准的 50%；Anthropic 把批量列为 50% 的节省（[platform.openai.com/docs/pricing](https://platform.openai.com/docs/pricing)、[claude.com/pricing](https://claude.com/pricing)，2026-11-10 核实）。缓存只有在稳定的提示前缀被复用且命中时才划算；批量需要能等待最长 24 小时的异步任务。具体数字请以各供应商自己的文档为准。

**同一个模型在不同网关上的价格会不同吗？**
会。一家追踪 235 家供应商的第三方聚合器发现，同一个开源模型在 96–126 家主机上的价格相差 13.2× 到 31.3×（[llmpricing.dev](https://llmpricing.dev/)，数据同步于 2026-11-09）。差距来自渠道档位、批量采购、多家主机提供同一开源模型、促销窗口，以及叠加其上的平台费。请用你自己的提示去比较实际到手价，而不是盯着标题价。
